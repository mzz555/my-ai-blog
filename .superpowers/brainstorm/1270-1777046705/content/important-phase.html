Important 阶段设计

5 个功能补全任务——后端接口 + 前端联调，每项独立可测

① 文章编辑（最高优先，当前编辑模式完全损坏）

Bug：点击"编辑"进入 /admin/articles/:id/edit 时，onMounted 只加载分类/标签， 从不调用 API 获取文章数据，表单永远是空的。
后端：新增 GET /api/articles/admin/{id}
  • 返回完整文章字段（含 tagNames、categoryId、status、isTop、allowComment、coverImage）
  • 需要 article:write 权限
  • ArticleController 已有 @GetMapping("/{slug}")，新增一个 @GetMapping("/admin/{id}")
前端：ArticleEditView 补全
  • 新增 getArticleById(id) 到 api/article.js
  • onMounted 中 isEdit 时调用，填充 form 所有字段
  • 新增封面图上传 UI（调用已有 uploadImage）
  • slug 从标题自动生成（拼音/英文），可手动覆盖
  • 按 Pencil Article Edit — Admin 样式重构布局

② 文章邻篇导航（上一篇 / 下一篇）

后端：GET /api/articles/{slug}/neighbors
// 响应结构
{ prev: {title, slug} | null,
  next: {title, slug} | null }

// 查询逻辑
prev = 同为 PUBLISHED，id < 当前，DESC limit 1
next = 同为 PUBLISHED，id > 当前，ASC limit 1
前端：PostDetailView 邻篇区域
  • API 函数 getArticleNeighbors(slug) 已存在，直接调用
  • 在文章内容底部渲染上/下篇卡片
  • 按 Pencil Article Detail — Dark 设计，使用 #13131E 卡片
  • 任一方向为 null 时隐藏对应卡片

③ 个人资料保存

后端：PATCH /api/users/profile
  • 从 JWT 获取当前用户 ID
  • 允许更新字段：bio（昵称已从 UserController 覆盖）
  • 返回更新后的用户对象
  • 在 AuthController 中添加（复用 JWT 工具）
前端：ProfileView 启用保存
  • 新增 updateProfile(data) 到 api/auth.js
  • 保存按钮调用，成功后刷新 Pinia userStore
  • 去掉 disabled，加 loading 状态

④ 标签编辑 + ⑤ 用户编辑（两个小型补全）

标签编辑：PUT /api/tags/{id}
  • TagController 新增一个 @PutMapping("/{id}")
  • TagService 调用 updateById（MyBatis-Plus 已有）
  • TagManageView 前端逻辑已完整，无需修改
用户编辑：PUT /api/admin/users/{id}
  • UserController 新增 @PutMapping("/{id}")
  • 请求体：{ nickname, roleIds: Long[] }
  • Service 层：更新 nickname + 重新分配 user_roles（先删后插）
  • 响应需包含 roles 数组（UserManageView 用于回显）
  • 前端无需修改
